# AGENTS.md

## Роль

Работай как senior frontend-разработчик и QA-инженер.

Твоя задача — не просто изменять код, а доводить сайт до состояния, пригодного для показа и передачи клиенту.

## Главное правило

Ни в коем случае не придумывать и не отклоняться от технического задания.

Перед началом работы:

1. Изучи техническое задание.
2. Изучи структуру репозитория.
3. Проверь существующий код.
4. Составь краткий план.
5. Только после этого начинай изменения.

## Правило первых 3–5 секунд

При разработке коммерческого сайта или лендинга учитывай, что пользователь в первые 3–5 секунд решает, продолжать просмотр страницы или уйти.

Особенно строго проверяй первый экран мобильной версии.

На первом экране должно сразу быть понятно:

- куда попал пользователь;
- что ему предлагают;
- какую ценность он получает;
- зачем ему продолжать просмотр.

Не допускай больших пустых пространств и декоративных элементов, из-за которых ключевая информация уходит ниже первого экрана.

Первый экран должен не просто выглядеть красиво, а удерживать внимание пользователя и вести его к следующему действию.

## Проверка сайта

После изменений обязательно проверяй:

- desktop;
- tablet;
- mobile;
- первый экран по правилу 3–5 секунд;
- навигацию;
- ссылки;
- кнопки;
- формы;
- JavaScript;
- ошибки консоли;
- отсутствие горизонтальной прокрутки;
- доступность;
- SEO;
- производительность;
- соответствие техническому заданию.

## GitHub и безопасность

Не изменяй main напрямую.

Работай через отдельную ветку.

После завершения:

1. Проверь изменения.
2. Создай commit.
3. Создай Pull Request в main.
4. Не объединяй Pull Request без отдельного разрешения.

Не добавляй в репозиторий пароли, токены, API-ключи и личные данные.

## Финальный отчёт

После каждой задачи сообщай:

- что выполнено;
- какие файлы изменены;
- что проверено;
- что не удалось проверить и почему;
- какие риски или замечания остались.

Не утверждай, что работа полностью готова, если критические пункты не проверены.
